local agent stack

O.L.L.I.

Ollama 기반 Go 에이전트에 파일 도구, subagent 위임, 세션 RAG, ComfyUI 이미지 생성, ACE-Step 오디오 생성을 붙인 로컬 작업 환경.

./build.sh ./bin/olli scripts/backends.sh status scripts/backends.sh start comfyui scripts/backends.sh start ace-step

runtime shape

작업은 로컬에서 돌고, 결과는 워크스페이스 안에 남습니다

에이전트는 Ollama 모델을 호출하고, 도구 실행과 생성 결과는 repository 내부 경계 안에서만 다룹니다.

Agent Core대화, 목표, 권한 모드, 세션 저장을 관리합니다.
Tool Registry파일 보기, 검색, 안전한 action, 이미지/오디오 생성 도구를 노출합니다.
Local BackendsOllama, ComfyUI, ACE-Step은 로컬 HTTP endpoint로만 연결됩니다.

delegation contract

Documenter와 Presenter는 실제 파일을 만들어야 성공입니다

이번 수정의 핵심은 subagent 보고서가 말만 SUCCESS로 끝나는 경로를 닫는 것입니다.

1. Delegate메인 agent가 역할별 subagent를 호출합니다.
2. Write쓰기 도구가 Markdown 또는 HTML artifact를 생성합니다.
3. Verifyrunner가 확장자, 존재, regular file, symlink 여부를 확인합니다.
4. Report메인 agent가 artifact 경로를 재검증한 뒤 성공을 보고합니다.

backend tools

이미지와 음악 생성은 HTTP backend가 맞습니다

Go agent는 생성 모델 런타임을 직접 안고 가지 않고, ComfyUI와 ACE-Step API를 안정적인 도구 backend로 호출합니다.

operator workflow

설치, 실행, 사용은 스크립트와 config로 분리합니다

모델 다운로드와 workflow 등록은 backend별로 다르므로 설치 스크립트가 런타임 준비를 맡고, 실제 모델/alias는 config.json에 명시합니다.

./scripts/install-prerequisites.sh --check-only ./scripts/install-prerequisites.sh --yes ./scripts/backends.sh start all ./scripts/backends.sh logs comfyui -f ./scripts/backends.sh status ace-step

safety posture

파일 경계는 성공 조건의 일부입니다

세션, subagent report, 생성 artifact는 워크스페이스 내부 regular file이어야 하며 symlink는 실패로 처리됩니다.

  • Documenter는 최소 하나의 .md artifact를 보고해야 합니다.
  • Presenter는 최소 하나의 .html artifact를 보고해야 합니다.
  • 성공 보고 전 메인 agent가 artifact 존재를 다시 확인합니다.
  • complete_goal은 agent 생성 시 등록되어 목표 종료 호출이 실패하지 않습니다.
